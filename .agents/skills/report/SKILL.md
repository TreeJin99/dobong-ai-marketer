# 주간 리포트 (report)

한 주 동안 내 사이트에 누가 어디서 왔는지 한 장으로 정리하는 일입니다. 숫자는 GA4 에 있는 것만 옮기고, 없는 숫자를 채워 넣지 않습니다.

## 준비
1. AGENTS.md 「나와 내 주제」「브랜드 규칙」(내 사이트 주소)을 읽습니다.
2. 이 폴더나 작업파일 폴더에 GA4 에서 내보낸 .csv 파일이 있는지 봅니다. 여러 개면 가장 최근 것을 쓰고 파일 이름을 알려 줍니다.
3. CSV 가 있으면 references/ga4_csv.md 를 읽고 숫자를 찾습니다.
4. CSV 가 없으면 아래 다섯 가지를 한 번에 묻습니다. GA4 「보고서」 화면에서 보고 불러 주면 됩니다.
   - 사용자 수 · 세션 수 · 참여 세션 수
   - 상위 유입 소스 3개와 각 세션 수 (「세션 소스/매체」)
   - 이벤트 수 (이벤트 이름별 숫자가 있으면 위에서 3개)
5. 기간을 정합니다. CSV 에 날짜가 있으면 그 날짜, 사용자가 말하면 그 날짜, 없으면 어제까지 7일입니다.

다섯 가지 중 끝내 못 받은 숫자는 표에 「확인 안 됨」으로 적습니다. 비슷한 숫자로 대신 채우지 않습니다.

## 쓰기
1. 숫자 표: 항목 · 이번 주 · 메모. 참여율(참여 세션 ÷ 세션)은 계산한 값이라고 메모에 적습니다.
2. 해석 세 줄: 표에 있는 숫자만 근거로 씁니다.
   - 어디서 왔나: 세션이 가장 많은 유입 소스
   - 무엇을 봤나: 이벤트 이름별 숫자가 있으면 가장 많은 것. 없으면 「확인 안 됨」
   - 무엇이 안 됐나: 숫자가 가장 작거나 0 인 곳. 추적 링크(utm)를 붙였는데 안 보이는 채널이 있으면 그 이름
3. 다음 주 할 일 세 가지: 해석 세 줄에서 바로 나오는 작은 일. 기준점 다시 기록하기(`$baseline`)를 하나 넣어도 됩니다.
4. 기준점 비교: 작업파일 폴더의 `기준점_*.md` 를 날짜순으로 읽고, 표에서 「내 이름 O·X」 칸의 O 개수를 셉니다. 처음 것과 마지막 것을 비교해 한 줄로 씁니다. 하나뿐이면 「비교하려면 $baseline 을 한 번 더 실행해 주세요」, 없으면 「기준점 없음」.

## 저장
1. 오늘 날짜로 `작업파일/주간리포트_YYYYMMDD.json` 을 씁니다. 형식은 `.agents/skills/report/assets/report_example.json` 과 똑같이 하고, 예시 숫자는 쓰지 않습니다.
2. `.agents/skills/report/assets/make_report.js` 를 `작업파일/` 에 복사합니다. 작업파일 폴더에 docx 패키지가 없으면 그 폴더에서 `npm install docx` 를 실행합니다.
3. 작업파일 폴더에서 `node make_report.js 주간리포트_YYYYMMDD.json ../주간리포트_YYYYMMDD.docx` 를 실행합니다.
4. 원본 글 `작업파일/주간리포트_YYYYMMDD.md` 에 같은 내용을 표와 글로 남깁니다.
5. 문서 맨 끝에는 「이 문서의 숫자는 AI가 옮겨 적은 것입니다. 쓰기 전에 GA4 화면의 숫자와 직접 한 번 대조해 주세요.」가 들어갑니다. 프로그램에 고정되어 있으니 지우지 않습니다.

끝나면 한 줄로 말합니다. 예: "주간리포트_20261021.docx 를 저장했습니다. 가장 많이 온 곳은 instagram(6회), 기준점 O 는 0개에서 1개가 됐습니다. 숫자는 GA4 화면과 직접 대조해 주세요."
