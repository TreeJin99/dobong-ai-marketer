# 기준점 (baseline)

오늘 날짜의 검색 결과를 기록해 두는 일입니다. 나중에 같은 질문으로 다시 검색해 달라진 것을 비교합니다. 처음에는 내 사이트가 안 나오는 것이 정상이며, 그것도 기록합니다.

## 준비
1. 이 폴더의 AGENTS.md 「나와 내 주제」와 사이트재료.md 「페이지 제목」「한 줄 소개」를 읽습니다.
2. 사용자에게 **내 사이트 주소**를 묻습니다. 아직 없으면 "없음"으로 진행합니다.
3. 웹 검색을 쓸 수 없는 상태면 멈추고 "codex --search 로 다시 켜 주세요"라고만 말합니다. 검색 없이 지어서 채우지 않습니다.

## 질문 5개 만들기
내 주제를 손님이 검색창에 칠 법한 짧은 말로 5개 만듭니다. 조건:
- 지역 + 주제 (예: "도봉구 무인 스터디카페")
- 주제 + 추천 또는 비교
- 주제 + 가격 또는 요금
- 주제 + 후기 또는 단점
- 주제어 + 사이트재료.md 「자주 묻는 질문」 중 하나의 핵심어 (예: "무인 스터디카페 밤늦게 혼자 안전"). 질문 문장을 그대로 쓰면 엉뚱한 결과가 나오므로 반드시 주제어를 앞에 붙입니다

질문 5개를 먼저 보여 주고, 사용자가 바꾸고 싶은 것이 있는지 한 번 묻습니다. 답이 없으면 그대로 진행합니다.

## 검색하고 기록하기
질문마다 웹 검색을 한 번씩 하고 아래를 기록합니다.
- 검색 결과에 나온 이름 상위 3개 (가게 · 사이트 · 글 제목)
- 내 사이트 주소 또는 「한 줄 소개」의 이름이 나왔는지: O 또는 X
- 결과를 한 줄로 요약 (검색 결과에 있는 말만 사용)

검색 결과에 없는 것은 쓰지 않습니다. 내 사이트가 안 나오면 X로 적습니다.

## 저장
- 파일 이름: `기준점_YYYYMMDD.docx` (오늘 날짜). 이 폴더에 저장.
- 원본 글 `기준점_YYYYMMDD.md`와 만들 때 쓴 프로그램은 작업파일 폴더에 둡니다.
- 문서 구성: 제목(내 주제 + 기준점) → 기록 날짜 · 내 사이트 주소 → 표(질문 / 상위 3개 / 내 이름 O·X / 한 줄 요약) → 마지막 줄에 "다음 확인 예정일". 사용자가 말한 날짜가 있으면 그 날짜, 없으면 기록일 + 7일.
- 워드 파일 규칙은 AGENTS.md 「[4] 형식」을 따릅니다 (Node docx, 맑은 고딕, 표 테두리).

끝나면 O 개수를 한 줄로 말합니다. 예: "5개 질문 중 내 이름이 나온 것 0개. 다음 확인 10월 19일."
