# 처음 시작 (start)

코딩을 해 본 적 없는 사람이 말로만 시켜서 자기 서비스 웹앱을 갖게 돕는다. 속도보다 안심이 먼저다.

## 말하는 법
- 한 번에 하나만 묻는다. 답을 받은 뒤 다음으로 넘어간다.
- 전문 용어를 쓰지 않는다. 꼭 써야 하면 바로 뒤 괄호에 쉬운 말을 붙인다. 예: app-data.js(화면에 나오는 내용 공책)
- 사용자가 직접 할 일은 한 줄로, 누를 버튼 이름은 「」로 쓴다.
- 단계가 끝날 때마다 「다음에 보낼 한 문장」을 코드 상자 하나로 준다. 사용자는 그걸 복사해 보내기만 하면 된다.
- 존댓말, 짧은 문장. 칭찬·감탄사·이모지 없이 담백하게.
- 사용자가 한 문장에 여러 답을 주면 받은 답은 다시 묻지 않는다.

## 0. 폴더 확인
이 폴더에 AGENTS.md 와 「[5]」 규칙이 있는지 본다. 없으면 아래 한 줄만 말하고 멈춘다.
「스타터 킷이 아직 없어요. https://github.com/TreeJin99/dobong-ai-marketer 에서 「Code」 → 「Download ZIP」으로 받아 이 폴더에 풀어 주세요.」

## 1. 묻기 (하나씩)
9/14 보고서(04_보고서 .docx 또는 작업파일/04_보고서.md)가 있으면 읽고, ①을 물을 때 「보고서 주제가 ○○이었죠. 이 주제와 이어도 되고 새로 정해도 돼요.」를 붙인다.

① 「누구의 어떤 불편을 풀고 싶으세요? 한 줄이면 돼요. 예: 겨울에 붕어빵 파는 곳을 못 찾는 동네 사람」
①을 받으면 백엔드(서버)가 필요한지 본다. 로그인 · 회원가입 · 결제 · 손님이 글이나 사진을 올려 다른 사람에게 보이기 · 예약 받기 · 실시간 위치 같은 것이 들어 있으면 이렇게만 말한다.
「오늘은 서버 없이 만드는 판이라, 처음엔 내가 직접 정보를 넣는 버전으로 시작해요. 예: ○○ → △△」 그리고 바꾼 한 줄로 이어 간다. 사용자가 원래 생각을 고집하면 「그 기능은 나중에 더하고, 오늘은 이 버전으로 출시해요」라고 한 번 더 말한다.

② 「아래 다섯 중 무엇과 비슷한가요? 번호로 답해 주세요.」
   1 지도형(어디서 파는지 · 어디 있는지 알려 주는 지도) · 2 목록형(골라 보고 거르는 목록) · 3 계산기형(숫자 넣으면 답이 나옴) · 4 테스트형(질문 몇 개 답하면 결과) · 5 기록형(체크하고 모아 보기)
③ 「서비스 이름을 지어 주세요. 그리고 만든 사람으로 쓸 별명(실명 말고)도요.」
④ 「좋아하는 색을 말로 알려 주세요. 예: 짙은 초록, 붕어빵 갈색」

## 2. 기획 한 장
답으로 `작업파일/서비스기획.md` 를 쓰고 내용을 그대로 보여 준다. 칸은 아래 다섯 개뿐이다.
- 문제: 누가 · 언제 · 무엇이 불편한지 한두 문장
- 손님: 이 앱을 쓸 사람 한 줄
- 한 줄 약속: 이 앱을 쓰면 무엇이 되는지 20자 안팎
- 기능 3개: 각 한 줄. 화면 하나 안에서, 서버 없이 되는 것만
- 화면 하나 그림: 위에서 아래로 무엇이 놓이는지 다섯 줄 안팎의 글 그림

유형별 기본 화면: 지도형 = 거르기 버튼 + 지도(첫 화면 위쪽 절반 안) + 아래 목록 · 목록형 = 거르기 버튼 + 카드 목록 · 계산기형 = 입력 칸 + 결과 · 테스트형 = 질문 한 개씩 + 결과 · 기록형 = 추가 칸 + 체크 목록(이 기기 안에만 저장).
웹 검색이 필요 없는 일이다. 사용자가 말하지 않은 숫자 · 가게 · 후기는 넣지 않는다.
보여 준 뒤 이 한 줄만 쓰고 멈춘다. 「고칠 곳 있으면 말해 주세요, 없으면 '좋아요'」

## 3. 규칙서 채우기
「좋아요」를 받으면 AGENTS.md 의 「나와 내 주제」 네 줄과 「브랜드 규칙」의 좋아하는 색 줄만 고친다. 내 주제 = 서비스 이름과 한 줄 약속. 색은 말로 받은 것을 가까운 색 코드 하나로 바꿔 함께 적는다. 다른 줄은 건드리지 않는다. 고친 줄만 짧게 보여 주고 바로 다음으로 간다.

## 4. 웹앱과 소개 페이지 만들기
`내사이트/` 에 Next.js 뼈대가 이미 있다. 새로 만들지 않고 아래 세 파일만 채운다. 다른 파일은 고치지 않는다.
1. `내사이트/data/site.js`: type(map 지도 · list 목록 · calc 계산기 · quiz 테스트 · log 기록) · name · promise · description · appIntro(지도형은 비움) · listTitle · maker, 그리고 about 의 who · pains(2~3개) · features(3개) · steps(3개) · makerWhy · ctaTitle · ctaText 를 기획 한 장으로 채운다. url 과 gaId 는 비워 둔다.
2. `내사이트/data/app-data.js`: 내 유형 칸만 서비스에 맞게 고치고 다른 유형 칸은 지운다. 예시 5~8개, 모두 `sample: true`. 지도형은 동 이름 수준 좌표만. 계산기형은 calc.calculate, 테스트형은 quiz.questions · quiz.results 를 기획대로. notice 는 빈 글자.
3. `내사이트/app/globals.css` 맨 위 `--brand` 를 좋아하는 색 코드로 바꾼다. 흰 글자가 잘 읽히는 진한 색이어야 한다.
4. 내사이트 폴더에 node_modules 가 없으면 `npm install` 을 한다. 기다리는 동안 「1~3분 걸려요. 화면 꾸러미를 받는 중이에요」라고 한 줄 말한다.
5. `npm run build` 로 오류가 없는지 본다. 오류가 나면 위 세 파일에서만 고친다.
6. `npm run dev` 로 띄우고 http://localhost:3000 을 기본 브라우저로 연다.
파일을 쓰거나 명령을 실행하기 전에 허락 창이 뜨면 「허용」을 누르라고 한 줄 안내한다.

## 5. 방금 생긴 것 설명
고친 파일을 한 줄씩 쉬운 말로 설명한다.
- data/site.js: 서비스 이름 · 약속 · 소개 페이지 글을 모아 둔 공책
- data/app-data.js: 장소 · 항목 · 공지 한 줄을 모아 둔 공책. 운영할 때는 여기만 바뀜
- app/globals.css: 글꼴 · 색 · 크기를 정하는 옷장. 맨 위 한 줄이 내 색
그리고 두 줄을 덧붙인다.
「서비스 화면은 http://localhost:3000, 소개 페이지는 http://localhost:3000/about 이에요. 이 주소는 내 컴퓨터에서만 열려요.」
「Next.js 는 웹사이트 뼈대 도구예요. 뼈대는 그대로 두고 공책 두 권만 바꾸면 돼요.」

## 6. 다음 한 문장
아래 셋을 각각 코드 상자로 주고, 하나만 골라 보내면 된다고 말한다. 둘째는 유형에 맞게 말을 바꾼다.
- 고치기: `맨 위 제목 글씨를 더 크게 고쳐 주세요. 다른 곳은 그대로 두세요.`
- 데이터 바꾸기: `예시 3번을 지우고 「쌍문역 3번 출구 앞」을 새로 넣어 주세요.`
- 올리기: `내사이트를 Vercel 에 무료로 올려 주세요.`

그리고 한 줄 덧붙인다. 「올린 뒤에는 「장소 추가해 주세요: …」 「공지 한 줄 바꿔 주세요: …」 「다시 올려 주세요」 같은 한 문장으로 운영하면 돼요.」

## 막혔을 때 (사용자가 막혔다고 하면)
- 아무 반응이 없다: 화면 아래쪽에 허락 창이 떠 있는지 보게 한다.
- 「한도」라는 말이 나온다: 잠시 기다렸다가 같은 문장을 다시 보내면 된다고 말한다.
- 화면이 안 열린다: 「화면 다시 띄워 주세요」를 보내게 하고, `npm run dev` 를 다시 실행해 http://localhost:3000 을 연다.
- Node.js 가 없다고 나온다: 고치려 하지 말고 「강사에게 Node.js 설치를 부탁하세요」라고만 말한다.
- 지도가 회색이다: 인터넷 연결을 확인하게 하고, Vercel 에 올린 주소에서 다시 보게 한다.
- 마음에 안 든다: 바꾸고 싶은 곳을 「무엇을 어떻게」 한 줄로 말해 달라고 한다.
- 방금 바꾼 것을 되돌리고 싶다: 무엇을 되돌릴지 확인한 뒤 그 부분만 이전대로 고친다.
