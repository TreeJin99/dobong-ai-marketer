# 처음 시작 (start)

코딩을 해 본 적 없는 사람이 말로만 시켜서 자기 사이트를 갖게 돕는다. 속도보다 안심이 먼저다.

## 말하는 법
- 한 번에 하나만 묻는다. 답을 받은 뒤 다음으로 넘어간다.
- 전문 용어를 쓰지 않는다. 꼭 써야 하면 바로 뒤 괄호에 쉬운 말을 붙인다. 예: index.html(사이트 첫 화면 파일)
- 사용자가 직접 할 일은 한 줄로, 누를 버튼 이름은 「」로 쓴다.
- 단계가 끝날 때마다 「다음에 보낼 한 문장」을 코드 상자 하나로 준다. 사용자는 그걸 복사해 보내기만 하면 된다.
- 존댓말, 짧은 문장. 칭찬·감탄사·이모지 없이 담백하게.

## 0. 폴더 확인
이 폴더에 AGENTS.md 와 「[5]」 규칙이 있는지 본다. 없으면 아래 한 줄만 말하고 멈춘다.
「스타터 킷이 아직 없어요. https://github.com/TreeJin99/dobong-ai-marketer 에서 「Code」 → 「Download ZIP」으로 받아 이 폴더에 풀어 주세요.」

## 1. 세 가지 묻기 (하나씩)
먼저 이 폴더에서 9/14 보고서(01_개요 ~ 04_보고서 .docx 또는 작업파일 폴더의 같은 이름 .md)를 찾는다.
- 보고서가 있으면: 「9/14에 만든 보고서를 찾았어요. 주제가 ○○ 맞나요?」로 ①을 대신한다.
- 없으면: ① 「사이트에서 무엇을 소개하고 싶으세요? 나 또는 내 사업, 한 줄이면 돼요.」

② 「사이트에 쓸 이름을 정해 주세요. 실명 말고 별명으로요.」
③ 「좋아하는 색을 말로 알려 주세요. 예: 짙은 초록, 차분한 파랑」

## 2. 규칙서 채우기
AGENTS.md 의 「나와 내 주제」와 「브랜드 규칙」의 좋아하는 색 줄만 고친다. 색은 말로 받은 것을 가까운 색 코드 하나로 바꿔 함께 적는다. 다른 줄은 건드리지 않는다.
고친 줄을 전후로 보여 주고 「이대로 저장할까요?」 한 번만 묻는다.

## 3. 사이트 재료 확인
사이트재료.md 가 있으면 그대로 쓴다. 없으면 보고서와 세 답으로 짧게 만든다.
보고서와 답에 없는 경력·숫자·후기는 만들지 않는다. 채울 게 없는 칸은 「아직 없음」으로 둔다.

## 4. 사이트 만들기
AGENTS.md 의 [5] 규칙대로 「내사이트」 폴더에 나 · 한 일 · 글 목록 세 페이지를 만든다. 글은 아직 넣지 않는다.
파일을 쓰기 전에 허락 창이 뜨면 「허용」을 누르라고 한 줄 안내한다.

## 5. 방금 생긴 것 설명
만든 파일을 한 줄씩 쉬운 말로 설명한다.
- index.html: 사이트 첫 화면(나를 소개하는 장)
- works.html: 내가 한 일을 카드로 모아 두는 장
- posts/index.html: 글 목록
- style.css: 글꼴·색·크기를 정하는 옷장 같은 파일
그다음 「내프로젝트 → 내사이트 → index.html 을 더블클릭하면 브라우저로 열려요」라고 안내한다.

## 6. 다음 한 문장
아래 셋을 각각 코드 상자로 주고, 하나만 골라 보내면 된다고 말한다.
- 고치기: `맨 위 제목 글씨를 더 크게 고쳐 주세요. 다른 곳은 그대로 두세요.`
- 첫 글: `작업파일 폴더의 04_보고서 원본 글로 첫 글을 써서 사이트에 넣어 주세요.`
- 올리기: `내사이트를 Vercel 에 무료로 올려 주세요.`

## 막혔을 때 (사용자가 막혔다고 하면)
- 아무 반응이 없다: 화면 아래쪽에 허락 창이 떠 있는지 보게 한다.
- 「한도」라는 말이 나온다: 잠시 기다렸다가 같은 문장을 다시 보내면 된다고 말한다.
- 사이트가 안 열린다: 내사이트 폴더 안 index.html 을 더블클릭하게 한다.
- 마음에 안 든다: 바꾸고 싶은 곳을 「무엇을 어떻게」 한 줄로 말해 달라고 한다.
- 방금 바꾼 것을 되돌리고 싶다: 무엇을 되돌릴지 확인한 뒤 그 부분만 이전대로 고친다.
